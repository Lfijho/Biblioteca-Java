Evolução do Sistema de Biblioteca: Da Interface Desktop Swing a uma Aplicação Web Full-Stack com Java Spring Boot e React.

Introdução / Visão Geral do Projeto Objetivo Inicial: Desenvolver um sistema de gerenciamento de biblioteca. Funcionalidades Centrais (Planejadas/Implementadas): Cadastro e gerenciamento de Livros. Cadastro e gerenciamento de Clientes. Registro e gerenciamento de Empréstimos e Devoluções. Geração de relatórios. Evolução Tecnológica: O projeto passou por uma significativa refatoração e modernização, migrando de uma aplicação desktop com interface gráfica Java Swing para uma arquitetura web moderna, utilizando um backend Java com Spring Boot e um frontend interativo com React.
Fase Inicial: Aplicação Desktop com Java Swing Tecnologias Principais: Java: Linguagem de programação base. Java Swing: Biblioteca para criação da interface gráfica do usuário (GUI) desktop. OkHttp & Gson: Bibliotecas utilizadas no SupabaseClient para interação com uma API externa (Supabase) via HTTP, para persistência de dados. Arquitetura: Classe App.java: Ponto de entrada principal, responsável por construir e gerenciar a interface Swing. Continha a lógica de interação do usuário (event listeners para botões) e chamava métodos de uma classe de lógica de negócio. Classe Biblioteca.java: Encapsulava a lógica de negócio principal (cadastrar cliente, cadastrar publicação, retirar/devolver livro, gerar relatório). Classe SupabaseClient.java: Responsável pela comunicação direta com o backend do Supabase (usando a API REST do Supabase) para persistir e recuperar dados. Utilizava OkHttp para as requisições HTTP e Gson para serializar/desserializar objetos Java para JSON. Classes de Modelo (POJOs): Cliente.java, Livro.java (e possivelmente Emprestimo.java em uma forma inicial) para representar os dados. Persistência de Dados: Utilização do Supabase como backend de banco de dados, acessado via sua API REST. Desafios/Limitações desta Fase (que motivaram a evolução): Aplicação desktop, limitada a usuários com o software instalado. Menor escalabilidade e acessibilidade comparada a uma aplicação web. A interação direta com a API do Supabase via OkHttp no cliente Swing, embora funcional, poderia ser centralizada em um backend dedicado para melhor gerenciamento, segurança e lógica de negócio mais robusta.
Fase de Transição: Introdução do Backend Spring Boot Objetivo: Criar uma API REST robusta para servir como backend para uma futura interface web, mantendo o Supabase como banco de dados. Tecnologias Adicionadas/Foco: Spring Boot: Framework para criação rápida de aplicações Java standalone e prontas para produção. spring-boot-starter-web: Para criar APIs REST. spring-boot-starter-data-jpa: Para facilitar a persistência de dados com JPA. Maven: Gerenciamento de dependências e build do projeto. PostgreSQL JDBC Driver: Para conectar o Spring Data JPA ao banco de dados PostgreSQL do Supabase. Hibernate: Implementação JPA padrão utilizada pelo Spring Data JPA. Principais Etapas de Desenvolvimento do Backend: Configuração do Projeto Maven (pom.xml): Adição do spring-boot-starter-parent. Inclusão das dependências do Spring Boot (web, data-jpa), driver PostgreSQL. Remoção de dependências não mais necessárias para o backend (ex: H2, se usado inicialmente para testes). Entidades JPA: Refatoração/criação das classes de modelo (Livro.java, Cliente.java, Emprestimo.java) como entidades JPA usando anotações (@Entity, @Id, @GeneratedValue, @ManyToOne, @Column, etc.). Ajuste de tipos de dados (ex: int para Integer para campos que podem ser nulos no banco). Repositórios Spring Data JPA: Criação de interfaces (LivroRepository, ClienteRepository, EmprestimoRepository) que estendem JpaRepository para fornecer operações CRUD e consultas customizadas (ex: findByIsbn, findByMatricula). Classes de Serviço (@Service): Criação de (LivroService, ClienteService, EmprestimoService) para encapsular a lógica de negócio. Injeção dos repositórios. Implementação de métodos para criar, buscar, atualizar, deletar entidades e lógicas específicas (ex: verificar limite de empréstimos, atualizar numEmprestimos do cliente). Uso de @Transactional para gerenciar transações com o banco de dados. DTOs (Data Transfer Objects): Criação de DTOs (ex: EmprestimoRequestDTO, DevolucaoRequestDTO) para desacoplar a API das entidades e modelar os dados de requisição. Controllers REST (@RestController): Criação de (LivroController, ClienteController, EmprestimoController) para expor os endpoints da API (@GetMapping, @PostMapping, @PutMapping, @DeleteMapping). Injeção dos serviços. Uso de @PathVariable e @RequestBody. Retorno de ResponseEntity para controlar status HTTP e corpo da resposta. Configuração da Aplicação (application.properties): Definição da porta do servidor. Configuração do datasource para conectar ao Supabase (PostgreSQL) usando o Session Pooler (URL, username do pooler, senha do banco). Ajuste de spring.datasource.url com ?prepareThreshold=0 para compatibilidade com o PgBouncer/Supabase Pooler. Configuração do dialeto do Hibernate e ddl-auto. Classe Principal da Aplicação Spring Boot: Criação de BibliotecaApplication.java com @SpringBootApplication e o método main para iniciar o servidor. Configuração de CORS (WebConfig.java): Implementação de WebMvcConfigurer para permitir requisições cross-origin do frontend React. Troubleshooting (Pontos Importantes Durante o Desenvolvimento): Resolução de UnknownHostException ao tentar conectar ao Supabase (envolvendo configuração de DNS do sistema, teste com nslookup e ping, e finalmente a mudança para o Session Pooler do Supabase). Resolução de FATAL: Tenant or user not found (ajustando o username para o formato do pooler). Resolução de ERROR: prepared statement "S_X" already exists (adicionando prepareThreshold=0 à URL JDBC). Correção de IllegalArgumentException: Can not set int field ... to null value (mudando int para Integer na entidade). Testes da API: Utilização do Postman para testar os endpoints CRUD para cada entidade, validando a funcionalidade do backend.
Fase de Desenvolvimento Frontend com React e Vite Objetivo: Criar uma interface de usuário web moderna e interativa para consumir a API Spring Boot. Tecnologias Adicionadas/Foco: React: Biblioteca JavaScript para construção de interfaces de usuário. Vite: Ferramenta de build e servidor de desenvolvimento rápido para projetos frontend. JavaScript (ES6+): Linguagem para o frontend. Axios: Cliente HTTP para fazer requisições à API Spring Boot. React Router DOM: Para gerenciamento de rotas e navegação SPA (Single Page Application). CSS: Para estilização. Principais Etapas de Desenvolvimento do Frontend: Setup do Projeto: Criação do projeto React usando npm create vite@latest. Instalação de dependências (axios, react-router-dom). Estrutura de Pastas: Organização em src/components (reutilizáveis, subdivididos por entidade como livro, cliente, emprestimo, e layout, common), src/pages (componentes de página inteira), src/services (apiService.js), src/styles (global.css, theme.css). Estilização Global e Tema: Definição de uma paleta de cores inspirada no GitHub em theme.css (usando variáveis CSS). Criação de global.css para estilos base. Importação dos CSS no main.jsx. Serviço de API (apiService.js): Centralização das chamadas Axios para todos os endpoints do backend Spring Boot. Componentes de Layout: Criação de Navbar.jsx para navegação principal usando Link do react-router-dom. Roteamento (App.jsx): Configuração de BrowserRouter, Routes, e Route para mapear caminhos URL para os componentes de página (HomePage, LivrosPage, ClientesPage, EmprestimosPage). Desenvolvimento das Páginas e Componentes CRUD: Livros: ListaLivros.jsx: Busca e exibe livros, com botões de editar/deletar. Gerencia estados de loading e erro. FormularioLivro.jsx: Para criar e editar livros, com inputs para os campos do livro e lógica de submit. LivrosPage.jsx: Orquestra a exibição da lista e do formulário. Clientes: ListaClientes.jsx: Similar ao ListaLivros. FormularioCliente.jsx: Similar ao FormularioLivro. ClientesPage.jsx: Orquestra os componentes de cliente. Empréstimos: FormularioEmprestimo.jsx: Para registrar novos empréstimos (input de matrícula e ISBN). ListaEmprestimos.jsx: Exibe empréstimos e permite registrar devoluções. EmprestimosPage.jsx: Orquestra os componentes de empréstimo, incluindo filtros. Gerenciamento de Estado: Uso de useState para gerenciar o estado local dos componentes (dados de formulário, listas, loading, erros). Uso de useEffect para buscar dados da API quando os componentes são montados ou quando dependências (como filtros) mudam. Comunicação Frontend-Backend: Resolução de erros de CORS (configurando WebConfig.java no backend). Tratamento de respostas de sucesso e erro das chamadas da API. Troubleshooting Frontend: Resolução de erros de importação de componentes (Failed to resolve import). Correção de Network Error e erros 500 Internal Server Error (identificando que eram relacionados a CORS ou problemas no backend que só se manifestavam com as requisições do frontend).
Estado Atual do Projeto (Maio de 2025) Backend Spring Boot funcional, conectado ao Supabase (via Session Pooler), com APIs REST para Livros, Clientes e Empréstimos. Frontend React com Vite funcional, consumindo as APIs do backend para realizar operações CRUD para Livros e Clientes, e operações de realizar empréstimo/devolução e listagem para Empréstimos.
